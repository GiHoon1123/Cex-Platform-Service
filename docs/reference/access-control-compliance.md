# 접근 통제·승인·감사의 근거와 미충족 요건

확인일은 2026-10-22다. 거래소·증권사의 공개 통제, 국내 적용 의무, 조직 인증과 개인 자격을 구분하고 이번 구현의 범위와 남은 운영 조건을 추적한다. **개업 적합성이나 인증 취득을 확인한 문서가 아니다.**

[구현·검증 기록](../decisions/012-platform-access-approval-audit.md) · [공통 규제 계획](../../../docs/roadmap/compliance-security.md)

## 근거를 적용하는 순서

사업 형태·취급 자산·수탁 여부·원화 취급·고객 관할을 확정하고, 법령 본문과 부칙에서 적용 여부·시행일을 판단한다. 법적 의무, 인증 심사 항목, 자율 보안 통제는 서로 다른 분류로 남긴다. 공개 제품 문서로 고객에게 제공하는 통제는 확인할 수 있지만 해당 회사 내부의 승인 체계·데이터베이스 구조까지 확인한 것은 아니다.

요구사항은 `근거 → 적용 조건 → 위험 → 정책 → 코드 → 테스트 → 운영 증적`으로 연결한다. 구현·로컬 검증·운영 검증·외부 심사 상태를 합치지 않는다. 아래의 “부분 구현”은 해당 법령·기준 전체 충족을 뜻하지 않는다.

## 개인 자격증과 사업 허가의 구분

[ISC2 CISSP](https://www.isc2.org/certifications/cissp/cissp-certification-exam-outline), [ISACA CISA](https://www.isaca.org/credentialing/cisa/get-cisa-certified), [ACAMS CAMS](https://www.acams.org/en/certifications/cams-certification?trk=public_profile_see-credential)의 공식 범위는 보안 설계·위험·감사·AML 지식의 검토 관점으로 참고한다. 개인의 시험·경력·유지 요건이 있는 자격이며, 이 코드를 작성하거나 해당 자격을 보유한다고 거래소 신고·조직 인증·사업 인가가 충족되는 것은 아니다. 자격 취득은 이번 작업의 완료 항목으로 두지 않는다.

## 반복 검토 기준

1. 설계 전: 사업 범위·근거·적용 조건·시행일·대안과 비용을 확인한다.
2. 구현 중: 인증 생략 경로, 공개 DTO의 개인정보, 같은 인물의 다중 계정, 회수/만료/동시성, 감사 실패를 재검토한다.
3. 완료 전: 실제 코드·자동 테스트·격리 실행 결과와 문서의 주장이 일치하는지 대조한다.
4. 운영 전: 미충족 목록의 담당자·기한·외부 증적을 확보한다. 코드 테스트 통과만으로 이 목록을 닫지 않는다.

이 문서는 접근 통제 사이클의 근거 목록이다. KYC·AML·수탁·이용자 보호 전체의 완전한 법률 검토를 대신하지 않으며, 세부 조문 확인이 남은 항목을 이미 충족한 것으로 표시하지 않는다.

## 운영자 MFA 후속 검토: 2026-10-22

[운영자 WebAuthn](../decisions/014-operator-webauthn-mfa.md)으로 비밀번호 단독 운영 세션을 제거했다. Coinbase·Kraken·IBKR의 공개 인증 기능, NIST·OWASP 수명 관리, Spring의 사용자 확인 우회 보안 공지를 재대조했다. 최초 기기 등록과 실제 서명 검증, 세션 교체·기한, 감사 트랜잭션을 로컬 검증한다. 사용한 키는 공개키 ID의 SHA-256 지문으로 감사에서 식별하며 원본 인증 본문은 기록하지 않는다.

[개인정보위 ISMS-P 안내서 게시](https://www.pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS217&mCode=G010030000&nttId=9862)의 2023-11-23 판본과 [금융보안원 금융권 점검항목](https://www.fsec.or.kr/bbs/detail?bbsNo=11386&menuNo=247)의 2023-12 자료·적용 대상 안내를 확인했다. 이것은 2026년 현행 법령의 모든 세부 요건을 확인했다는 뜻이 아니다. 인증 기준·법적 의무·자율 강화의 구분을 유지한다. 계정/권한의 회수·정기 재검토, 실제 복수 인물의 신원 확인과 복구 승인, 실물 기기·TLS·모니터링·외부 감사 보존·인허가 증적은 남아 있다.

## 복구·권한 수명 후속 검토: 2026-10-22

[기기 폐기·복구·권한 수명 관리](../decisions/015-operator-recovery-and-access-lifecycle.md)에서 예비 키로 분실 키 폐기, 다른 두 인물의 복구 요청/승인, 신고 직후 접근 차단, 승인 뒤 새 키·서명, 30일 이내 권한 재검토·만료·즉시 회수를 구현·로컬 검증했다. 최초 부여는 웹/금융 워커/DDL이 없는 전용 관리 JAR로 분리했다. 고객·금융 기록은 유지한다.

이 결과는 신원 확인·통지의 자동 이행을 의미하지 않는다. 코드는 외부 신원/통지 증적의 참조를 고정하고 독립된 현재 운영 인물의 승인을 요구한다. 실제 증적 원본·통지 전달·인사 변동 연동·정기 검토 알림·보존/파기·일반 역할 변경/상시 부여 승인·업무별 추가 인증·운영 심사는 남아 있다. NIST/OWASP와 거래소·증권사 공개 사례의 선택 근거, 현행 고시 표기 재확인과 적용 한계는 해당 결정 문서에 연결했다.


## 일반 역할 부여·변경 후속 검토: 2026-10-22

[일반 역할 승인과 업무별 서명](../decisions/016-operator-role-approval-and-bound-authentication.md)을 추가했다. 정상 운영의 신규 직원/직무 변경은 요청자·승인자·대상자 세 인물 분리, 불변 내용·버전·기한, 실행 직전 WebAuthn 증명과 감사 트랜잭션을 거친다. 거래소 Kraken의 관리 변경 승인, IBKR의 업무 승인자, OWASP의 서버 측 업무 결합·단기 일회성·최종 실행 확인을 적용했다. 기존 설치 검증기를 공유하며 새 의존성은 없다.

이 추가 인증의 구현 범위는 역할 요청의 승인·거절이다. 기존 복구·권한 기한 재검토·거래 제한 승인은 기존 인증 방식이며 다음 확장 대상으로 남긴다. 비웹 관리 JAR의 사용 제한·승인·외부 기록, 실제 인물/통지 증적, DB/OS 관리자 접근·별도 불변 저장, 운영 HTTPS·실물 기기·브라우저·조직 심사는 여전히 필요하다.

현행 고시 페이지의 2026-07-01 시행 표기는 재확인했으나 조문 본문은 이번 조회에서 추출되지 않았다. KISA 일부 페이지는 502, 개인정보 포털 과거 링크는 안내 화면으로 이동했다. 이를 최신 조문·심사 기준 전체 확인으로 표시하지 않는다. 법적 의무·인증 기준·자율 보안 강화의 구분과 기존 미충족 표는 유지한다.


## 기존 승인 업무의 서명 결합 후속 검토: 2026-10-22

[네 업무 승인 서명](../decisions/017-bound-approval-for-existing-operations.md)으로 역할·복구·접근 기한 재검토·고객 거래 제한의 승인과 거절을 업무 종류·요청 ID·고정 내용·세션·행위자·만료·일회성에 결합했다. 요청 당시 담당자 버전을 불변 보관해 역할 변경 후 복귀해도 기존 요청을 사용할 수 없다. 거래 제한 승인의 비밀번호 재인증 분기는 삭제했고 로그인 비밀번호와 그 추측 제한은 유지한다.

옛 요청·금융·감사 이력은 보존하며 새 결합 정보가 없는 과거 대기 요청은 재신청한다. 과거 역할 전용 단기 인증 옵션만 폐기한다. 일반 보안키의 내용 표시, 외부 신원·통지 원본, 관리 JAR/DB/OS 접근 통제, 조직 심사·인허가·실물 기기·운영 HTTPS는 여전히 별도 조건이다. 분실 신고와 긴급 회수의 즉시 차단 정책은 유지한다.

Kraken·IBKR·OWASP·Spring 공식 자료와 현행 고시 페이지 표기·금융권 ISMS-P 점검 자료를 다시 대조했다. 고시 본문 조문별 세부 적용과 전체 규제 충족은 미확인으로 남긴다. 다음 업무는 로드맵의 고객 확인(KYC)·거래 가능 정책이며, Didit 현재 명세와 개인정보·계약 조건을 확인해 연결한다.

## 2026-10-22 고객 신분 확인 후속 계층

[Didit 신분 확인과 신규 주문 정책](../decisions/018-didit-identity-verification-and-trading-policy.md)으로 로그인·외부 신분 확인·운영자 수동 거래 제한을 별도 조건으로 구현했다. 서명된 전체 본문, 앱/환경/워크플로/버전과 고객/세션 연결, 문서/생체 검사, 불변 수신 이력과 감사 실패 롤백을 로컬에서 검증한다. 실제 공급사 연동과 전체 CDD/AML·인증/신고 완료로 표시하지 않는다.

[금융정보분석원 고객확인 안내](https://www.kofiu.go.kr/kor/policy/amls05.do)의 고객 신원 외 실소유자·거래 목적·위험별 추가 확인·지속 관리 범위는 후속 요건이다. [업무규정 이력 페이지](https://www.law.go.kr/LSW/admRulInfoP.do?admRulSeq=2100000284076&chrClsCd=010201)는 2026-08-20·제2026-2호 및 연혁 표시만 확인했다. 이번 추출에서 조문 전체·최신 적용 관계는 미확인이므로 구체 의무 충족의 근거로 확대하지 않는다. 공급사 국외 이전·위탁·보유/파기·학습 사용 설정·DPA와 실제 조직/심사 증적은 별도 확인 조건이다.

## 2026-10-23 플랫폼 KYC 결과 대사

[누락 웹훅 복원·최근 확인 기한](../decisions/019-platform-kyc-reconciliation.md)에서 원래 서명 이벤트·현재 결정 대조, 영속 임대/변경 번호, 전체 복원과 필수 감사의 원자적 커밋을 추가했다. 마지막 확인이 15분을 넘거나 근거가 일치하지 않으면 신규 주문을 거부한다. 5분 재조회·15분 확인 기한·2분 임대는 자체 위험 통제 정책이며 법정 수치·공급사 보장이 아니다. 전체 고객확인·AML·실제 공급사 연동·인허가/인증 완료를 뜻하지 않는다. 키 교체·원문 반환 권한·보유/삭제·국외 이전·대기열/만료 경보·조직 증적은 운영 전 확인 조건이다.

## 2026-10-23 고객 신고와 초기 위험 평가 후속 상태

[고객 신고·신원 대조·초기 평가](../decisions/020-customer-declaration-and-initial-risk.md)를 추가했다. FIU 고객확인 설명과 거래소/증권사 공개 고객 정보 업무, Didit 신원/AML 명세를 대조했다. 암호화 신고·서명된 실제 신원/검색 대상 일치·불명/PEP/기타 검토 사유·중복 신호·현재 평가의 주문 통제를 로컬에서 검증한다. 입력·국내 자동 범위·기간은 자체 정책이며 법정 기준으로 표시하지 않는다.

법령 본문/부칙의 이번 재조회는 완전 추출에 실패했으므로 최신 세부 조항 전부 확인으로 표시하지 않는다. 주민등록번호/여권번호 수집·번호 지문 생성은 없다. 이름·생일·국적 지문은 고유 인물 증명이 아니다. 전체 CDD/AML·국내 제재/PEP 목록·실제 지속 모니터링·EDD 심사·신고/인증·개인정보 처리 근거/보유/삭제·계약과 운영 증적은 남아 있다. 개인 자격의 지식 범위와 사업 인허가·조직 인증을 계속 구분한다.

## 2026-10-23 EDD 사건과 독립 검토

[EDD 사건·독립 결정](../decisions/021-edd-case-and-independent-review.md)에서 기존 검토 이력을 재신고로 지우지 못하게 하고, 실제 평가/서명 이벤트에 결합한 보고서·별도 인물 보안키 결정·제한적인 정보 불일치 종결을 로컬 검증했다. PEP/AML 등은 종결하지 않으며 자료 대기/준법 회부로 유지한다.

이번에는 [특금법 제5조의2 조문정보](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1022860887)의 표시 시행 2026-10-02·제21857호 본문을 읽었다. 앞선 본문 추출 실패와 구분한다. 고객 확인과 의심 시 목적/원천, 내부 지침·방법, 확인 불가 시 신규 거래 거절/관계 종료, 보고 여부 검토의 범위를 확인했다. 코드의 REFERRED는 법정 보고·관계 종료의 이행이 아니다. 시행령/고시·전체 부칙·사업별 적용·조직/고위 경영진·실제 증빙/감시·보존/파기·신고/인증은 여전히 별도 확인 조건이다. 개인 자격을 사업 인허가나 조직 인증으로 해석하지 않는다.

## 실제 구현과 함께 읽기 · 2026-10-23

이 문서의 관련 동작을 확인할 현재 코드다. 메서드·설정의 일부이며 독립 실행 예제가 아니다. 계획이나 과거 검토 전체가 구현·검증됐다는 뜻은 아니다.

출처: [OperatorSessionPolicy.java](../../src/main/java/dustin/cex/domains/security/OperatorSessionPolicy.java#L19) · [전체 구현 설명·트레이드오프·작성한 테스트](../decisions/015-operator-recovery-and-access-lifecycle.md)

```java
public RefreshToken requireFresh(User user,UUID sid,UserRole... roles) {
    if(user==null || !user.isAuthenticationAllowed() || user.getRole()==UserRole.CUSTOMER
            || Arrays.stream(roles).noneMatch(r->r==user.getRole())) throw denied();
    var session=tokens.findBySessionId(sid).orElseThrow(OperatorSessionPolicy::denied);
    LocalDateTime now=LocalDateTime.now();
    // 두 값 모두 Long 객체다. 참조 비교는 작은 정수 캐시 밖의 정상 사용자까지 거부하므로 값으로 비교한다.
    if(!session.getUserId().equals(user.getId()) || session.getRevoked() || !session.getExpiresAt().isAfter(now)
            || !session.hasVerifiedMfa() || !session.getMfaVerifiedAt().plusMinutes(5).isAfter(now)) throw denied();
    return session;
}
```

`Long.equals`는 객체 참조가 아닌 사용자 ID 값을 비교한다. 세션 회수·만료·MFA 시각은 현재 저장값으로 확인하며, JWT에 들어 있던 역할만 믿지 않는다. 호출자는 사용자 행을 먼저 잠가야 한다.

이번 보강은 문서 변경이다. 신규 제품 테스트는 0개이며 제품 테스트는 재실행하지 않았다. 소스와 발췌의 일치를 별도로 검사했다. 과거 실행 결과와 현재 소스의 동작 범위는 연결한 구현 기록에서 구분한다.

## 2026-10-23 증빙 보관·열람 단계

[구현·실제 코드·테스트·공식 근거](../decisions/022-edd-evidence-storage-and-access.md)에 증빙 수집 목적 제한, 독립 키·인증 문맥, 최근 MFA·담당자/독립 열람, 원본/열람본 분리와 필수 감사를 추가했다. RECEIVED_UNVERIFIED는 실사·EDD 해소·인증 통과 상태가 아니다. 개인정보 보호법 제29조와 제21조 제3항의 시행 2026-09-11 표기를 다시 확인했으며, 전체 법적 수집/보유/파기·분리 보존·정확한 고시·업종 적용·조직 증적·운영 심사·실제 키 관리와 파일 검사/파서 격리는 미충족 과제로 유지한다. 상세 근거 URL과 확인 범위는 연결 문서를 따른다.

## 2026-10-23 주소 증빙 내용의 독립 검토

[023 코드·선택·실제 테스트·공식 근거](../decisions/023-address-document-independent-review.md)에서 현재 자료 제공 영수증, 이름·주소만의 감사 열람, 암호화한 사람 관찰·현재 평가 결합, 별도 인물의 독립 재입력과 전용 업무별 서명을 연결한다. Kraken/Coinbase 주소·추가 자료 안내, FFIEC 검사 절차·FINRA 보관 NASD 03-34 역사 자료와 국내 제5조의2/개인정보 제29조를 다시 구분해 대조했다. 90일은 제품 정책이고, 승인 결과는 문서 내용 검토이며 진위·실제 거주·EDD 해소·거래 허용·외부 인증 통과가 아니다. 전용 역할·문서/키/현재 상태의 운영 증적과 022의 보존/파기/검사·인프라 조건은 남아 있다.

## 2026-10-23 자금 발생·수취 자료와 내부 체결의 독립 검토

[024 실제 코드·트레이드오프·테스트·공식 근거](../decisions/024-source-of-funds-pair-and-trade-review.md)에서 두 SOURCE_OF_FUNDS 자료의 현재 열람·암호화 관찰·이름/지급인/금액/통화/기간 대조와 별도 인물의 재입력·전용 서명을 연결한다. 과거 본인 체결은 실제 수신 키와 TRADE 원장의 순지출에 연결하며 최초 반입을 외부 입금으로 취급하지 않는다. 관찰 승인도 사건 OPEN·거래 차단을 유지하고 불일치 사유를 지우지 않는다.

국내 제5조의2는 조회 화면의 시행 2026-10-02·법률 제21857호를 확인했다. Kraken/Coinbase 공개 자료 요청 절차와 AUSTRAC 갱신 2026-10-13 자료를 참고하되 호주 의무를 국내 의무로 표시하지 않는다. 법령/하위 규정 전체·신고/인증을 이번에 전수 검증한 것은 아니다. 내부 체결 연결은 외부 수취·발급기관·위변조·환전 경로·복수 거래 자금 배정의 독립 검증을 대신하지 않는다. 재산 형성·PEP/제재 실체 판단·모니터링·STR·관계 종료/잔여 자산 업무와 운영 키/DB 권한/보존·파기 조건은 남아 있다.

완료 전 FINRA Regulatory Notice 19-18(2019-05-06)의 고객 자료·자금 원천 불일치 신호도 재대조했다. 미국 증권사 대상 과거 안내이며 신호 자체를 위법 판정으로 보지 않고 추가 조사·보고 판단과 분리하는 설계 참고로만 사용한다. 최신 국내 신고 기준·운영 승인으로 표시하지 않는다.

## 2026-10-23 선택 기간 순재산 증감의 독립 관찰 검토

[025 실제 코드·트레이드오프·작성한 테스트](../decisions/025-wealth-period-independent-review.md)에서 세 SOURCE_OF_WEALTH 자료의 현재 열람과 자산/부채·기간별 순증감을 대조한다. 대출·매각 총액을 순재산에 더하지 않고, 통화가 다르면 합계를 만들지 않는다. 차이는 독립 승인 뒤에도 남으며 사건 OPEN·거래 차단을 유지한다. 재산 신고가 없는 기존 CDD의 자금 원천 필드를 재산 진술로 재사용하지 않는다.

Kraken/Coinbase의 SoF/SoW 구분·기간/복수 자료, AUSTRAC 표시 갱신 2026-10-13의 위험별 독립 근거 대조, SEC Investor.gov의 자산-부채 계산을 확인했다. 국내 제5조의2는 조회 화면 시행 2026-10-02·법률 제21857호를 대조했고 FINRA 19-18은 미국 증권사 대상 2019-05-06 과거 안내로 구분한다. 세 자료/12행/동일 통화는 제품 정책이며 법정 양식이 아니다. 전체 법령·하위 규정·신고/인증을 새로 전수 확인한 것은 아니다.

기초 재산의 실제 원천·전체 자산/부채의 완전성·소유권/평가·별도 고객 재산 진술·발급기관 진위·외부 독립 자료·세금/환전·다중 기간과 실체 판단은 미완료다. 차이 0이나 내용 승인으로 EDD·PEP/제재·STR·관계 종료·사업 신고/인증을 완료하지 않는다. 키/DB 권한/외부 감사 보존·보유/파기·국외 이전·운영 복원 조건은 기존 대조표와 022에서 이어 관리한다.

## 2026-10-23 EDD 결정 근거 묶음과 독립 제공 확인

[026 실제 코드·트레이드오프·명명된 테스트](../decisions/026-edd-dossier-and-independent-inspection.md)에서 자료 요청/수신과 주소·자금·재산 검토 상태를 원문·금액 없이 불변 보존한다. 기존 업무별 서명에 목록 전체 해시를 결합하고, 독립 승인자의 본인 세션으로 25개 단위 모든 페이지를 제공받아야 한다. GET 역사 조회는 승인용 제공 영수증을 만들지 않으며 새 근거가 생기면 옛 서명을 거절한다. 필수 감사 실패 시 새 묶음·제공 기록도 해당 트랜잭션에서 취소한다.

Coinbase 계정 검토 공개 절차, AUSTRAC 표시 갱신 2026-10-13, 미국 증권사 대상 과거 FINRA 19-18, 국내 제5조의2 조회 화면 시행 2026-10-02·법률 제21857호를 참고한 범위와 공식 링크를 026에 기록했다. 공개 안내가 각 기관의 내부 스냅샷 구현을 설명한 것으로 해석하지 않는다. 전체 법령·하위 규정·사업 신고·인증 기준을 새로 전수 확인한 결과도 아니다.

목록 제공은 실제 독해·문서 진위·외부 기관/은행/체인·소유권/적법성 검증이 아니다. 관찰 승인의 부정 사유는 목록에 남으며 OPEN/REFERRED의 거래 차단을 유지한다. 내부 식별자는 연결 가능한 개인정보이고, 보존/파기·외부 감사/KMS·DB 권한·국외 이전·실제 조직/운영은 기존 미충족 조건을 따른다.

## 2026-10-23 서명 AML 후보 근거·개별 조사

[027 실제 코드·트레이드오프·테스트](../decisions/027-signed-aml-evidence-and-investigation.md)에서 서명 검증된 최신 live 이벤트·평가·사건에 묶인 최소 후보 근거를 보존한다. 전체 상태가 In Review/Declined여도 같은 세션의 실제 AML 위험 자료는 조사로 연결하며 거래는 허용하지 않는다. 담당자 의견은 공급사 상태 변경·제재 해소·법정 보고가 아니고 기존 EDD 서명의 전체 근거에 포함된다. 독립 재입력이나 새 승인 종류를 추가하지 않는다.

Didit 공식 AML 보고서의 검색 노드·후보 ID·신원/위험 점수 구분과 웹훅 계약, 업비트 공개 고객확인 절차와 국내 제5조의2를 대조했다. 번호/미디어/임의 속성/URL은 보관하지 않고 최소 신원·후보 속성과 메모를 각각 기존 키로 보호한다. 이는 공급사 계약·국내 목록 완전성·실제 외부 진위/인물 판정·조직 권한·보유/파기/국외 이전·키 교체·신고/인증을 완료한 상태가 아니다. 근거와 미확인 범위는 027을 따른다.

## 2026-10-23 AML 오탐 종결과 기한부 허용

[028 실제 코드·근거·테스트](../decisions/028-aml-false-positive-resolution.md)는 국내 고객확인 의무와 공급사 데이터 계약, 자체 보수적 종결 정책을 구분한다. 과거 AML 검토뿐인 사건에서 새 서명 결과·전체 후보 유지·완전한 다른 생일·현재 모든 조사·독립 결정을 확인한다. 원래 REVIEW_REQUIRED를 보존하고 실제 승인 내용에 일치하는 기간만 신규 주문을 허용한다. 최근 MFA·전체 근거 열람·업무별 서명·필수 감사·경합 원자성은 기존 통제를 재사용한다.

Didit 공식 보고서/개요, 업비트 공개 고객확인 안내, 국내 제5조의2의 조회 화면 시행 2026-10-02·법률 제21857호를 재대조했다. 24시간 상한·완전한 생일 차이는 법정 요구가 아닌 자체 정책이다. 공급사 자동 오탐 분류는 외부 사람 검토 완료가 아니고 현재 대사 성공도 명단 최신성·국내 완전성 보장이 아니다. 확인 불가·확정 위험의 관계 유지/거절·종료·의심거래 보고 여부 검토와 실제 운영·계약·조직 조건은 계속 별도다. 이번 일부 구현만으로 전체 규제/신고/인증 완료를 표시하지 않는다.

## 2026-10-23 비공개 의심거래 보고 여부 검토

[029 실제 코드·근거·테스트](../decisions/029-confidential-reporting-review.md)는 법률 제21857호·시행 2026-10-02의 제4조, 감독규정 고시 제2026-3호·시행 2026-10-02의 제3조/제13조를 실제 본문 응답과 대조한다. 합당한 의심·사유 보존·누설 금지와 내부 AML 목적 제공 예외, 보고책임자 결정 후 제출 기한을 구분했다. KoFIU·KONA 공개 흐름, 빗썸 AML 공지·삼성증권 자료·FCA 안내를 확인했고 업비트 교육은 본문 조회 실패와 검색 요약 확인 범위를 명시했다.

현재 승인된 준법 회부의 지정 작성자/승인자·암호화 결론/사유·별도 전체 페이지 제공·STR_REVIEW 서명·필수 감사와 불변 결정을 구현한다. 일반 EDD 목록에는 비공개 판단을 복사하지 않고 역할 외에 실제 두 인물 배정을 검사한다. 공통 보안 감사에는 업무 존재·해시·서명 종류가 남는다. 실제 보고책임자 선임·전담 권한/교대·긴급 외부 보고·법정 기한/접수/보완·전사 미처리 큐·관계 거절/종료·운영 보존/파기는 미완료다. 내부 미보고도 거래 권한을 열지 않는다. 기존 DB 변환/운영 배포나 전체 신고/인증 충족은 아니다.

## 2026-10-23 확정 보고 필요의 조회와 후속 관찰

[030 실제 코드·트레이드오프·테스트](../decisions/030-reporting-queue-and-followup.md)는 감독규정 고시 제2026-3호·시행 2026-10-02 본문에서 제3조 기한과 보고/접수 통보·제8조 보정/보존을 재대조한다. FIU 포털 공개 접수 API 계약은 확인하지 못했으며 자동 전송·접수 성공값을 발명하지 않는다. KoFIU/KONA 공개 흐름과 Stripe의 오류/멱등 처리, PostgreSQL 16의 커밋 가시성/행 값 비교를 참고했다.

원래 지정된 두 인물에게 승인 후보를 25개씩 검증하고 실제 REPORT_REQUIRED만 반환한다. 빈 items에도 next가 있으면 진행하며 갱신은 처음부터 다시 시작한다. 현재 사건/신고·미보고·고객 비활성화로 과거 확정 필요를 숨기지 않는다. 외부 참조/메모는 암호화·최소 열람·불변/멱등 기록하며 필수 감사 실패로 반환/저장을 막는다. 접수 참조 관찰도 FOLLOW_UP_REQUIRED이며 법정 기한은 확인 필요로 표시한다. 내부 24시간 목표는 법정 3영업일이나 실제 보고책임자 시각의 계산값이 아니다. 전사 미처리/고립 사건·재배정·기관 접수 진위·보정·실제 제출/기한 충족은 미완료다.

## 2026-10-24 보고 후속 업무의 독립 인계·고립 발견

[031 실제 코드·선택·명명된 테스트](../decisions/031-reporting-custody-and-orphan-recovery.md)는 Camunda 8.9의 배정/업무 상태 분리와 8.10 개별 권한, 국내 법률 제21857호·시행 2026-10-02 제4조/제5조와 FCA의 해외 책임 체계를 구분해 대조한다. 원래 판단을 고치지 않는 논리 세대·직전 근거 해시·행 잠금·독립 STR_CUSTODY 서명과 현재 후속 배정을 구현한다. 법정 보고책임자 임면이나 기관 등록을 대신하지 않는다.

현재 담당자 또는 두 담당자 모두 권한이 없는 때에만 요청하며, 새 두 담당자와 요청자에게서 독립된 승인자가 본인 제공/서명으로 확정한다. 일반 운영 역할의 고립 발견은 원문 없는 최소 메타데이터 목적 권한이며 전담 조직 분장·직무별 감독·인사 인물 UUID의 실명 신뢰·실제 기관/운영은 미완료다. 인계는 원래 필요/내부 목표/법정 의무·금융 제한을 해제하지 않는다. 과거 요청자/실제 결정자는 원문 없는 결과만 재확인할 수 있다.


## 2026-10-24 확정 보고 필요의 전사 점검

[032 설계·코드·테스트](../decisions/032-reporting-supervision.md)는 현재 유효하고 최근 MFA를 마친 APPROVER에게 실제 확정 보고 필요의 최소 메타데이터를 제공한다. 담당자가 정상이어도 원래 승인 시각/24시간 내부 목표·현재 배정 세대·담당자 ID와 사용 가능 여부·최근 관찰 저장 시각을 확인한다. 비공개 사유·관찰 원문·외부 결과 방향/참조·인물 UUID·원문 지문은 반환하지 않는다.

필터 뒤 서비스에서 현재 권한을 다시 검사하고 감사 실패 시 목록을 반환하지 않는다. 원래/현재 담당자의 원문·후속 기록·인계 자격, 금융 제한은 별개로 유지한다. 광역 승인 역할에 업무 존재가 노출되는 비용을 명시하며 전담 준법 직무·법정 책임자·실제 제출/법정 기한·운영 감독 증적 충족으로 표시하지 않는다. 새 스키마·승인 종류·의존성은 없다.


## 2026-10-24 고객 관계 종료 절차 개시

[033 실제 코드·선택·작성한 테스트](../decisions/033-relationship-exit-initiation.md)는 현재 승인된 준법 회부와 명시적인 고객확인 불가 판단에 두 인물의 독립 RELATIONSHIP_EXIT 서명을 결합한다. 요청자/고객/지정 승인자 버전·전체 근거·현재 평가·본인 제공·서명 방향과 감사를 함께 검증한다. 새 11종 제약과 불변 세 표를 요구하며 옛 10종 스키마를 자동 변환하지 않는다.

불변 승인은 신규 주문의 별도 차단 근거다. 고객확인 정상화·일반 거래 제한 해제가 이를 지우지 않는다. 이미 접수된 명령·동일 키 재조회·기존 주문 취소와 자산/원장은 보존하며 고객은 자신의 EXIT_PENDING 상태만 읽는다. Spring Security 7.1.1의 기본 저장 금지 헤더를 재사용한다. 직원의 판단은 외부 사실 진위나 법적 요건 자동 판정이 아니고, 실제 관계 종료/자산 반환·입출금 사유/통지·오판의 독립 철회·STR 검토/제출·조직/계약/운영 증적은 계속 미완료다.


## 종료 개시의 독립 철회 · 2026-10-24

[034 구현·공식 근거·실제 코드·테스트](../decisions/034-exit-rescission.md)는 원래 참여 OPERATOR의 요청과 원래 두 인물에게서 독립된 APPROVER의 EXIT_RESCISSION 서명으로 지정 종료 개시의 효과만 제외한다. 원래 APPROVED 기록·STR 판단/후속·자산/예약·다른 거래 제한은 보존한다. 세 인물은 자체 정책이며 법정 인원 수로 주장하지 않는다. 현재 평가/사건·버전·전체 당시/현재 근거 제공을 재검사하고, 옛 철회 재조회는 새 회부/종료 결정을 해제하지 않는다.

새 승인 종류 12종·세 불변 표·활성 뷰와 두 DB 효과 검사가 필요하다. READ COMMITTED 고객 행 잠금 뒤 현재 효과를 읽고 지원하지 않는 격리는 거부한다. 옛 11종 제약/영구 승인 인덱스는 자동 변환하지 않는다. 원래 인물 부재 시 인계·고객 이의 접수/알림·최종 종료/자산 반환·기관 제출/운영 심사는 별도 미완료다. [확정 증적](exit-rescission-verification-2026-10-24.json)에서 실행 범위를 확인한다.
