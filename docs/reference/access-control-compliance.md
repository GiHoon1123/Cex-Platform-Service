# 접근 통제·승인·감사의 근거와 미충족 요건

확인일은 2026-10-22다. 거래소·증권사의 공개 통제, 국내 적용 의무, 조직 인증과 개인 자격을 구분하고 이번 구현의 범위와 남은 운영 조건을 추적한다. **개업 적합성이나 인증 취득을 확인한 문서가 아니다.**

[구현·검증 기록](../decisions/012-platform-access-approval-audit.md) · [공통 규제 계획](../../../docs/roadmap/compliance-security.md)

## 근거를 적용하는 순서

사업 형태·취급 자산·수탁 여부·원화 취급·고객 관할을 확정하고, 법령 본문과 부칙에서 적용 여부·시행일을 판단한다. 법적 의무, 인증 심사 항목, 자율 보안 통제는 서로 다른 분류로 남긴다. 공개 제품 문서로 고객에게 제공하는 통제는 확인할 수 있지만 해당 회사 내부의 승인 체계·데이터베이스 구조까지 확인한 것은 아니다.

요구사항은 `근거 → 적용 조건 → 위험 → 정책 → 코드 → 테스트 → 운영 증적`으로 연결한다. 구현·로컬 검증·운영 검증·외부 심사 상태를 합치지 않는다. 아래의 “부분 구현”은 해당 법령·기준 전체 충족을 뜻하지 않는다.

## 개인 자격증과 사업 허가의 구분

[ISC2 CISSP](https://www.isc2.org/certifications/cissp/cissp-certification-exam-outline), [ISACA CISA](https://www.isaca.org/credentialing/cisa/get-cisa-certified), [ACAMS CAMS](https://www.acams.org/en/certifications/cams-certification?trk=public_profile_see-credential)의 공식 범위는 보안 설계·위험·감사·AML 지식의 검토 관점으로 참고한다. 개인의 시험·경력·유지 요건이 있는 자격이며, 이 코드를 작성하거나 해당 자격을 보유한다고 거래소 신고·조직 인증·사업 인가가 충족되는 것은 아니다. 자격 취득은 이번 작업의 완료 항목으로 두지 않는다.

## 반복 검토 기준

1. 설계 전: 사업 범위·근거·적용 조건·시행일·대안과 비용을 확인한다.
2. 구현 중: 인증 생략 경로, 공개 DTO의 개인정보, 같은 인물의 다중 계정, 회수/만료/동시성, 감사 실패를 재검토한다.
3. 완료 전: 실제 코드·자동 테스트·격리 실행 결과와 문서의 주장이 일치하는지 대조한다.
4. 운영 전: 미충족 목록의 담당자·기한·외부 증적을 확보한다. 코드 테스트 통과만으로 이 목록을 닫지 않는다.

이 문서는 접근 통제 사이클의 근거 목록이다. KYC·AML·수탁·이용자 보호 전체의 완전한 법률 검토를 대신하지 않으며, 세부 조문 확인이 남은 항목을 이미 충족한 것으로 표시하지 않는다.

## 운영자 MFA 후속 검토: 2026-10-22

[운영자 WebAuthn](../decisions/014-operator-webauthn-mfa.md)으로 비밀번호 단독 운영 세션을 제거했다. Coinbase·Kraken·IBKR의 공개 인증 기능, NIST·OWASP 수명 관리, Spring의 사용자 확인 우회 보안 공지를 재대조했다. 최초 기기 등록과 실제 서명 검증, 세션 교체·기한, 감사 트랜잭션을 로컬 검증한다. 사용한 키는 공개키 ID의 SHA-256 지문으로 감사에서 식별하며 원본 인증 본문은 기록하지 않는다.

[개인정보위 ISMS-P 안내서 게시](https://www.pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS217&mCode=G010030000&nttId=9862)의 2023-11-23 판본과 [금융보안원 금융권 점검항목](https://www.fsec.or.kr/bbs/detail?bbsNo=11386&menuNo=247)의 2023-12 자료·적용 대상 안내를 확인했다. 이것은 2026년 현행 법령의 모든 세부 요건을 확인했다는 뜻이 아니다. 인증 기준·법적 의무·자율 강화의 구분을 유지한다. 계정/권한의 회수·정기 재검토, 실제 복수 인물의 신원 확인과 복구 승인, 실물 기기·TLS·모니터링·외부 감사 보존·인허가 증적은 남아 있다.

## 복구·권한 수명 후속 검토: 2026-10-22

[기기 폐기·복구·권한 수명 관리](../decisions/015-operator-recovery-and-access-lifecycle.md)에서 예비 키로 분실 키 폐기, 다른 두 인물의 복구 요청/승인, 신고 직후 접근 차단, 승인 뒤 새 키·서명, 30일 이내 권한 재검토·만료·즉시 회수를 구현·로컬 검증했다. 최초 부여는 웹/금융 워커/DDL이 없는 전용 관리 JAR로 분리했다. 고객·금융 기록은 유지한다.

이 결과는 신원 확인·통지의 자동 이행을 의미하지 않는다. 코드는 외부 신원/통지 증적의 참조를 고정하고 독립된 현재 운영 인물의 승인을 요구한다. 실제 증적 원본·통지 전달·인사 변동 연동·정기 검토 알림·보존/파기·일반 역할 변경/상시 부여 승인·업무별 추가 인증·운영 심사는 남아 있다. NIST/OWASP와 거래소·증권사 공개 사례의 선택 근거, 현행 고시 표기 재확인과 적용 한계는 해당 결정 문서에 연결했다.
